### Q1. 파이썬 기본 자료형 세 개 + 각각 `type()`에 넣고 출력 시 정확한 결과
**답**: 숫자, 문자형, 불 / `type("str)`, `type(int)`, `type(bool)`
**결과**: △ 부분 정답

**해설**: 자료형 셋은 방향 맞음 — 정확히는 **문자열(str) · 숫자(int) · 불(bool)** ("문자형"보다 "문자열").
핵심 오류는 `type()` 쪽. 자료형을 확인하려면 그 자료형의 **값(예시)**을 넣어야 함:

```python
print(type("안녕"))   # <class 'str'>
print(type(13))       # <class 'int'>
print(type(True))     # <class 'bool'>
```

- `type(int)`·`type(bool)`처럼 자료형 **이름**을 넣으면 결과는 `<class 'type'>`이 나옴 (int·bool 자체가 'type'이라는 자료형의 객체). → 5/26 Q1 `type(type(273))` = `<class 'type'>`에서 봤던 그것. 5일 공백 사이 이 구분이 흐려진 흔적.
- `type("str)`는 따옴표가 안 닫혀 **SyntaxError**. `type("str")`이면 `<class 'str'>`.
- 출력 형태(`<class '...'>`) 자체를 안 적음 — 질문의 절반이 "정확히 어떻게 찍히는지"였음.

### Q2. `"크로니클"`에서 `[0]` / `[-1]` / 범위 밖 `[10]`
**답**: 크 / 크 / 인덱스 에러
**결과**: △ 부분 정답

**해설**:
- `[0]` = **크** ✓
- `[-1]` = **클** (답 "크"는 ❗). 음수 인덱싱은 **뒤에서부터** — `-1`이 맨 끝 글자. 5일 공백에 흐려진 자리 하나 더.
- `[10]` = **IndexError** ✓ (5/26엔 이름 몰라 △였는데 이번엔 잡음. 정확한 표기 `IndexError`, index out of range)

```
크   로   니   클
0    1    2    3
-4   -3   -2   -1
```

### Q3. `"크로니클"`에서 `[1:3]` / `[1:]` / `[:2]`
**답**: 로니 / 로니클 / 크로
**결과**: ✓ 정답 (3/3)

**해설**: 양수 슬라이싱 완벽. 끝 인덱스 미포함(`[1:3]`은 3 직전=2까지), 끝 생략=끝까지(`[1:]`), 시작 생략=0부터(`[:2]`) 전부 정확. → 5/26 최약점이 슬라이싱이었는데 양수 기본은 확실히 굳음.

### Q4. `"크로니클"[-3:-1]`
**답**: 로니
**결과**: ✓ 정답

**해설**: `-3`(로)부터 `-1` 직전(=`-2`, 니)까지. 끝 미포함이라 `-1`(클)은 빠짐 → 로니. 음수도 슬라이싱 방향은 왼→오로 동일. Q2에서 `[-1]` 틀렸던 음수 방향이 표 한 번 보고 바로 교정됨 — "모르는" 게 아니라 "흐려졌던" 거였다는 신호.

### Q5. `"크로니클"[-4:0]` 결과 + 이유 (5/26 ❗❗❗ 재시험)
**답**: 아무것도 안 나옴 / 빈 값. "0의 자리는 없으니까, 근데 IndexError는 안 나니까 빈 값"
**결과**: △ 부분 정답 (결과 ✓ · 이유 ❗) — 5/26에 `[-4:0]`을 "크로니클"이라 답한 ❗❗❗에서 **결과는 교정됨**

**해설**:
- 결과 정확: 빈 문자열 `''`.
- "0의 자리가 없다"는 ❗ — 인덱스 `0` 자리는 "크"로 엄연히 있음.
- 진짜 이유: 슬라이싱의 끝 숫자는 **"그 직전에서 멈춰"**라는 멈춤 신호. `[-4:0]`에서 시작 `-4`=위치 0(크), 끝 `0`="위치 0 직전". 시작과 끝이 **같은 지점** → 자를 게 없음 → 빈 문자열.
- "에러 안 나니까 빈 값" 역추론은 결과적으론 맞는 보정 (슬라이싱은 범위 벗어나도 에러 X — 인덱싱과 다른 점). 다만 그건 "왜 빈 값인지"가 아니라 "에러는 아니다"만 말해줌.
- 한 줄 정리: **끝 숫자 = 멈출 위치(그 직전까지). `0`이면 시작도 하기 전에 멈추니 빈 값.**

### Q6. `"크로니클"[::-1]` 결과 + 콜론 개수·의미
**답**: 콜론 2개 (✓). 의미·결과는 "모르겠다" — 덮지 않고 정직하게 신고
**결과**: ❗ (step 개념 미학습) — 단, 막힘을 덮지 않고 신고한 건 5/27 "곤란→덮음" 패턴의 교정

**해설**:
- 콜론 2개 ✓. 슬라이싱 풀 형식은 `[시작:끝:step]` — 콜론 2개면 끝에 **step** 자리가 있다는 뜻.
- **step** = 몇 칸씩, 어느 방향으로 진행할지. 생략하면 `1` (한 칸씩, 왼→오).
- `-1` = 한 칸씩 **뒤로** → 전체 뒤집기.
- `[::-1]` = 시작·끝 생략(전체) + step `-1` → **클니로크**.
- 콜론 개수 총정리:
  - 0개 `[a]` → 인덱싱 (글자 1개)
  - 1개 `[a:b]` → 슬라이싱 (범위)
  - 2개 `[a:b:c]` → 슬라이싱 + step
- 일반 슬라이싱 `[a:b]`는 방향이 **항상 왼→오**라 그 자체로는 뒤집기가 안 됨. 뒤집으려면 반드시 step `-1`. 그래서 `[::-1]`이 뒤집기 전용 표현. → 5/26 Q2에서 `[-1:]`(슬라이싱)과 `[::-1]`(step)을 헷갈렸던 부분의 정체.
