### 01-1 파이썬이란?

**파이썬 = 인터프리터 언어.** (1991년 귀도 반 로섬 개발 / 이름은 코미디쇼 몬티 파이썬에서 — 외울 것 X, 상식)

**핵심 개념: 인터프리터 vs 컴파일**

- 인간의 언어(코드)와 기계의 언어(0·1)는 다르다 → 반드시 **번역**이 필요하다.
- **컴파일이든 인터프리터든 둘 다 "번역"을 한다. 차이는 그 번역을 "언제" 하느냐다.**

| | 컴파일 (C#) | 인터프리터 (파이썬) |
|---|---|---|
| 번역 시점 | 실행 전, 전체를 한 번에 | 실행 중, 한 줄씩 |
| 빌드 결과물(.exe) | 있음 | **없음** |
| 실행 방식 | 번역본(.exe)을 돌림 | 코드를 그때그때 읽으며 돌림 |

- 비유: 컴파일 = **자막 번역**(미리 통째로 번역→자막 완성→상영은 빠름) / 인터프리터 = **동시통역**(미리 준비 없이 한 문장씩 실시간 통역→바로 시작 가능하나 매번 통역해서 더 느림).
- QA 연결: C# "빌드 깨짐(컴파일 에러)"은 실행 전 전체 번역 단계에서 막힌 것. 파이썬은 그 단계가 없어 에러가 있어도 **그 줄을 실행할 때 비로소** 터지고 앞 줄까지는 돌아감.

> ⚠️ [클로드 보충 — 원문엔 없음] 자막/동시통역 비유, 컴파일이 실행 속도 빠르다는 점은 도서관 01-1 원문에 없는 클로드의 보충 설명(사실이긴 함). 원문 01-1은 "인터프리터 = 한 줄씩 해석·실행" 수준으로 짧게만 다룸.

**❗ 내가 두 번 미끄러진 자리 (= 진짜 약점):**
1. "해석"의 반대를 국어사전식으로 추상화라고 봄 → 여기서 해석 = "기계어로 번역"이라는 뜻.
2. "파이썬=번역 담당, 컴파일=실행 담당"으로 역할을 나눠버림 → **둘 다 번역+실행 다 함. 차이는 타이밍뿐.**

### 01-2 파이썬의 특징

> 외울 절 아님 — "파이썬이 어떤 성격의 언어인가" 파악용. 혼자 읽고 인출.

**파이썬의 특징 (원문 6가지):**
1. 인간다운 언어 — 사람 사고방식 그대로 표현. 기계 사고체계에 맞출 필요 없음. 예: `if 4 in [1,2,3,4]: print("4가 있습니다")` → "만약 4가 1,2,3,4 중에 있으면 출력"로 영어 문장처럼 읽힘. (`in`은 03-1에서도 본 그것)
2. 문법이 쉬워 빠르게 배움 — 에릭 레이먼드 하루 만에 원하는 프로그램 작성.
3. 무료·오픈소스 — 라이선스 지키면 누구나 자유롭게 사용·복제·배포·수정.
4. C와 찰떡궁합 — **뼈대는 파이썬(쓰기 편함), 속도 필요한 구간만 C(빠름)**로 만들어 포함.
5. 간결하다 — 펄이 한 일을 100가지로 한다면 파이썬은 가장 좋은 1가지. 들여쓰기 강제(안 하면 실행 안 됨) → 가독성.
6. 개발 속도가 빠름 — "Life is too short, You need python" (책 전체 예제로 계속 등장).

> 🟡 [보충·정설] C로 만들어 파이썬에서 쓰는 대표 예: NumPy, Pandas (겉은 파이썬, 속은 C라 빠름). 01-3 원문에도 "NumPy는 C로 작성되어 빠르다" 나옴. NumPy 공식: https://numpy.org

**❗ 미끄러진 자리 (퀴즈 보강 후보):**
- C와 파이썬의 빠름/느림 방향을 처음에 **거꾸로** 말함 → **C가 빠름, 파이썬이 느림.** (1-1의 "컴파일=실행 빠름"과 연결)
- 둘을 나누는 기준을 "명령 vs 실행"으로 잘못 잡음 → 정답은 **"뼈대 vs 속도 구간".** 둘 다 실행되는 코드임. 각자 잘하는 걸 맡기는 분업.

> 📌 페이스 원칙(오늘 자가발견): "100% 이해하고 넘어가기"가 과거 학습을 죽였음. → 엉망이라도 쭉 달리고 인출로 미끄러진 자리만 표시 → 나중에 퀴즈로 보강. (단 "끄덕이고 넘기기"와는 다름: 인출+표시는 반드시 함)

## 퀴즈 (2026-06-03) — 1장(개념) 인출

> 1장은 개념 절이라 코드 실행 문제 X, "개념을 내 말로 인출". 책/노트 안 보고 진행. 결과 5/5 ⭕.

**Q1.** 인터프리터 언어란? 컴파일과 차이는?
→ ⭕ "둘 다 인간언어→기계어 번역. 인터프리터=동시통역, 컴파일=미리 통번역." 핵심어 "언제"가 표현에서 묻혔으나 개념 정확. 완성형: **둘 다 번역하되, 차이는 번역을 "언제" 하느냐(컴파일=실행 전 통째 / 인터프리터=실행 중 한 줄씩).**

**Q2.** 파이썬·C 찰떡궁합 — 각자 담당과 빠른 쪽?
→ ⭕ "파이썬=뼈대, C=속도, C가 빠름." 방향·기준 정확. ❗단 "C=실제 실행 담당"이라는 잔여 오해 재출현 → 교정: C는 "실행 담당"이 아니라 **"속도 급한 구간만" 담당.** 파이썬도 실제 실행됨(95%는 파이썬, 병목 5%만 C). 예: numpy 겉은 파이썬·속은 C.

**Q3.** "인간다운 언어"의 뜻은?
→ ⭕ "if·in 등 구성요소가 영어(인간 언어)고, 0/1 아닌 사람 말에 가까운 규칙으로 짠다." 보강: 단어가 영어인 것뿐 아니라 **생각하는 순서·방식 그대로 옮길 수 있음**이 핵심.

**Q4.** 파이썬의 "간결함" 철학(펄 대비)?
→ ⭕ "파이썬=가장 좋은 하나의 방법 선호 / 펄=여러 방법." 핵심 대비 정확.

**Q5.** 파이썬이 약한 것 + 도메인 연결?
→ ⭕ "모바일 네이티브 앱 직접 제작 약함, 그럴 바엔 다른 언어가 빠르고 편함." 모바일 게임 QA 도메인과 즉시 연결.

**❗ 보강 후보 (퀴즈 재출제용):**
- "C = 실행 담당" 오해 (정답: 속도 급한 구간만 담당, 파이썬도 실행됨) — 오늘만 2회 출현, 끈질김.
