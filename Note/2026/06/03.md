## 학습 내용 (01장)

### 01-1 파이썬이란?

**파이썬 = 인터프리터 언어.** (1991년 귀도 반 로섬 개발 / 이름은 코미디쇼 몬티 파이썬에서 — 외울 것 X, 상식)

**핵심 개념: 인터프리터 vs 컴파일**

- 인간의 언어(코드)와 기계의 언어(0·1)는 다르다 → 반드시 **번역**이 필요하다.
- **컴파일이든 인터프리터든 둘 다 "번역"을 한다. 차이는 그 번역을 "언제" 하느냐다.**

| | 컴파일 (C#) | 인터프리터 (파이썬) |
|---|---|---|
| 번역 시점 | 실행 전, 전체를 한 번에 | 실행 중, 한 줄씩 |
| 빌드 결과물(.exe) | 있음 | **없음** |
| 실행 방식 | 번역본(.exe)을 돌림 | 코드를 그때그때 읽으며 돌림 |

- 비유: 컴파일 = **자막 번역**(미리 통째로 번역→자막 완성→상영은 빠름) / 인터프리터 = **동시통역**(미리 준비 없이 한 문장씩 실시간 통역→바로 시작 가능하나 매번 통역해서 더 느림).
- QA 연결: C# "빌드 깨짐(컴파일 에러)"은 실행 전 전체 번역 단계에서 막힌 것. 파이썬은 그 단계가 없어 에러가 있어도 **그 줄을 실행할 때 비로소** 터지고 앞 줄까지는 돌아감.

> ⚠️ [클로드 보충 — 원문엔 없음] 자막/동시통역 비유, 컴파일이 실행 속도 빠르다는 점은 도서관 01-1 원문에 없는 클로드의 보충 설명(사실이긴 함). 원문 01-1은 "인터프리터 = 한 줄씩 해석·실행" 수준으로 짧게만 다룸.

**❗ 내가 두 번 미끄러진 자리 (= 진짜 약점):**
1. "해석"의 반대를 국어사전식으로 추상화라고 봄 → 여기서 해석 = "기계어로 번역"이라는 뜻.
2. "파이썬=번역 담당, 컴파일=실행 담당"으로 역할을 나눠버림 → **둘 다 번역+실행 다 함. 차이는 타이밍뿐.**
