# 유니티·C# — 2026-06-08

> 역량 빌드업 트랙 시작(파이썬과 별개 트랙). 목표 = "카드 한 장 띄우고 클릭하면 반응". 구현·C# 입문.
> 진행 방식: 한 걸음씩 직접 조작 → 스크린샷 → 다음. 코드 통째 복붙 X, 매 줄 "왜"를 한국어로 풀며.

## 학습 내용

### 1. 게임오브젝트 = 부품(컴포넌트) 조립 — [오늘의 핵심]

**유니티의 근본 사고방식: 화면의 물체(게임오브젝트)는 "부품"을 붙여서 만든다.**

하얀 카드(Square) 하나에 부품 셋을 붙였다:

| 부품 | 담당 |
|---|---|
| Sprite Renderer | 어떻게 보일지 (하얀 네모로 보이게) |
| Box Collider 2D | 어디까지가 클릭 범위인지 (감지판) |
| Card (스크립트) | 클릭당하면 뭘 할지 (행동) |

- 🔴 [보충·비유] 카드 = 몸, 부품 = 장기. "보는 눈(Sprite Renderer) / 닿는 걸 느끼는 피부(Collider) / 반응하는 뇌(Script)"를 각각 끼워 넣은 셈. 어디까지나 와닿게 하려는 비유 — 정확히는 "컴포넌트를 조립한 게임오브젝트".

### 2. 클릭 감지 = OnMouseDown + Collider

- `OnMouseDown()` = 유니티가 약속한 이름의 함수. 이 오브젝트가 클릭되면 유니티가 알아서 이 이름을 찾아 실행한다. (그래서 철자 정확히 써야 작동 — 이름이 곧 약속)
- ❗ **결정적: Collider가 없으면 OnMouseDown은 아예 호출 안 됨.** 그림(Sprite)만 있으면 눈엔 보여도 클릭이 안 잡힌다. Box Collider 2D가 "여기까지가 카드"라는 경계를 그어줘야 비로소 클릭이 잡힌다.

### 3. 변수와 부품 가져오기

- `SpriteRenderer sr;` → 값을 담는 빈 상자(**변수**) 선언. SpriteRenderer를 담을 예정.
- `bool selected = false;` → 켜짐/꺼짐만 갖는 스위치(**bool**). "지금 선택됐나?"를 기억.
- `void Awake()` → 게임 시작 시 딱 한 번 자동 실행되는 함수.
- `sr = GetComponent<SpriteRenderer>();` → "내 몸에 붙은 SpriteRenderer 부품을 찾아와" 상자 sr에 담기. 미리 쥐어둬야 나중에 `sr.color`로 색을 바로 만질 수 있음.

### 4. 토글과 분기

- `selected = !selected;` → `!` = "반대로". 클릭마다 스위치를 **뒤집음**(true↔false). = 토글.
- `if (selected) { 노랑 } else { 흰색 }` → 상태에 따라 행동이 갈림. 그래서 누를 때마다 노랑↔흰색.

### 막혔던 것 (실전 트러블슈팅)

- **증상**: 코드·Collider 다 맞는데 클릭해도 콘솔에 아무것도 안 뜸. 에러도 없음(조용한 무반응).
- **원인**: 프로젝트에 New Input System(새 입력 방식)이 깔려 있는데, `OnMouseDown`은 레거시(옛) 입력 방식. 프로젝트가 "새 방식만"으로 설정돼 있어 OnMouseDown을 호출조차 안 함.
- **해결**: Edit → Project Settings → Player → Other Settings → **Active Input Handling**을 `Both`로 변경 → 에디터 재시작. (둘 다 켜두면 마찰 최소)

## 퀴즈 (2026-06-08) — 첫날 인출

> 스크린샷·코드 안 보고 머리에서 인출. 결과 1.5/4 수준(개념 미끄러짐 있었으나 핵심 약점을 정확히 노출 = 수확).

**Q1.** 카드에 붙인 부품 셋과 각 역할은?
→ ❌(부분) "Card 스크립트 하나 붙이고 그 안에 콘솔 기능 + 색 기능 두 개" 로 답함. 두 가지 어긋남:
   ① 콘솔 버전과 색 버전은 별개 기능이 아니라 **하나를 다른 하나로 교체**한 것(코드를 통째로 갈아끼움).
   ② 부품은 스크립트 하나가 아니라 **셋**(Sprite Renderer / Box Collider 2D / Card). → "부품(컴포넌트)"과 "스크립트 안 기능"을 혼동.

**Q2.** 왜 카드 위에서만 반응하고 배경에선 안 했나?
→ ❌ "카드에 코드를 넣었기 때문" 으로 답함. 그것만으론 "왜 하필 네모 안에서만"을 설명 못 함. 정답: **Box Collider 2D**가 클릭 범위를 그어줬기 때문. (Q1에서 Collider를 빠뜨린 게 그대로 이어짐)

**Q3.** `selected = !selected;` 가 하는 일?
→ ⭕ "터치될 때마다 스위칭". 토글 핵심 정확. 완성형: 켜짐↔꺼짐을 매번 뒤집음.

**Q4.** `GetComponent<SpriteRenderer>()` 는?
→ (정직하게 "모르겠다") 추측 X = 좋은 태도. 정답: 내 몸에 붙은 SpriteRenderer 부품을 찾아와 sr 상자에 담음. 미리 쥐어둬야 나중에 색을 바로 만질 수 있음.

**❗ 보강 후보 (다음 세션 재출제):**
- **부품(컴포넌트) vs 스크립트 안 기능 혼동** — 한 약점이 Q1·Q2 둘 다 관통. 끈질긴 1순위.
- **Box Collider 2D의 역할** = 클릭 범위 정의. OnMouseDown은 Collider 없으면 작동 안 함.

## 종합 결과 (강점 / 약점 / 보강)

- **강점**: 모르는 건 추측으로 메우지 않고 "모르겠다"로 정직하게 비움(Q4). 손으로 직접 조작하며 트러블슈팅(입력 방식 충돌)까지 스스로 밟음.
- **오늘 굳은 것**: 토글(`!`로 상태 뒤집기) / if-else 분기 / OnMouseDown이 클릭 시 자동 호출된다는 감 / 입력 방식 충돌 해결 경험.
- **약점·보강(1순위)**: "게임오브젝트 = 부품 조립"의 부품 개념. 카드가 그냥 네모가 아니라 [보이는 부품 + 눌리는 걸 아는 부품 + 행동하는 부품]의 조립체라는 것. Box Collider의 역할. → 다음 세션에서 단단히 굳히면 나머지가 줄줄이 풀리는 핵심 길목.
- **페이스**: 첫날 목표("카드 띄우고 클릭 반응") 완수. 콘솔 로그 → 게임 화면 내 상태 변화(색)로 진전. 다음 단계는 "부품 개념 복습 + 카드에 데이터(이름·코스트) 넣기" 후보.
