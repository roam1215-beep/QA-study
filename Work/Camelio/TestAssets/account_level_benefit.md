## 3. HOLD — Testability 부족

현재 QA 치트/편의 기능으로 계정 레벨 또는 EXP를 원하는 상태로 만들 수 없다. `SLM-0108`이 해결되거나 대체 세팅 수단이 생기기 전까지 아래 Coverage는 억지로 완료 처리하지 않는다.

- 한 번에 2레벨 이상 상승
- 초과 EXP의 다음 레벨 이월
- 실제 최대 레벨 도달 및 MAX 처리
- 최대 레벨 이후 EXP 처리
- 여러 레벨의 미수령 보상 누적 후 일괄 수령
- 특정 LOCKED / CLAIMABLE 상태의 반복 생성
- 수령 상태의 재접속 Persistence / 재수령 방지
- 계정 레벨 기반 UNLOCK 타입의 실제 상태 전이
  - 현재 구현/데이터 Evidence도 충분하지 않으므로 Testability 확보 후 Scope부터 재확인

## 4. Regression Focus

다음 계정 레벨 보상 QA에서 우선 재확인할 가치가 높은 항목:

- Lv.1에 잘못된 수령 가능 보상이 다시 생기지 않는지
- 수령 완료 아이콘/상태가 즉시 동기화되는지
- `모두 받기` 연타/중복 요청으로 중복 지급되지 않는지
- 동일 레벨 보상 팝업 중복 생성 방지
- Testability 확보 후 다중 레벨업 / EXP 이월 / MAX / 누적 보상
- Testability 확보 후 서버 상태와 재접속 후 UI 상태 일치

## 5. Test Case Handoff

- 현재 Google Drive의 상세 TC는 이 Recovery Coverage 기준으로 아직 정리되지 않았다.
- Testability 확보 전에는 실행할 수 없는 TC를 형식적으로 늘리지 않는다.
- 우선 TC 승격 대상:
  1. 기본 EXP 획득 → 레벨 상승 → 보상 수령
  2. `모두 받기` 중복 지급 방지
  3. 수령 상태 Persistence
  4. 다중 레벨업 + 잔여 EXP
  5. MAX Boundary
  6. 계정 레벨 UNLOCK이 실제 Scope일 경우 대표 1개 Flow
- 후속 연출 일감 반영 시 CLAIMABLE 표현은 해당 작업 기준으로 Delta 추가한다.
